# Contributing to MerOb

Thanks for your interest in contributing! We welcome all kinds of contributions — bugs, features, docs, ideas.

---

## Quick Start

1. **Fork the repo** → `github.com/germainia17-dev/MerOb/fork`
2. **Clone your fork**
   ```bash
   git clone https://github.com/YOUR_USERNAME/MerOb.git
   cd MerOb
   ```
3. **Create a feature branch**
   ```bash
   git checkout -b feature/your-feature-name
   ```
4. **Make changes** and test
5. **Commit** with clear messages
6. **Push** and open a pull request

---

## What to Contribute

### 🐛 Bug Reports
Found a bug? [Open an issue](../../issues) with:
- What you were doing
- What happened
- What you expected
- Screenshots/videos if helpful
- Your OS & browser version

### ✨ Features
Have an idea? [Start a discussion](../../discussions) first to get feedback. Then:
1. Fork the repo
2. Create a feature branch
3. Keep changes focused and small
4. Write tests if applicable
5. Open a PR with a clear description

### 📚 Documentation
- Fix typos in README, INSTALL, docs
- Add examples or clarifications
- Translate docs to other languages
- Improve code comments

### 🎨 Design & UI
- UI improvements
- Better icons or visual hierarchy
- Accessibility fixes
- Mobile responsiveness

---

## Code Style

- **JavaScript** — Use `const`/`let`, no `var`. Keep functions small.
- **Python** — Follow PEP 8. Use `black` for formatting.
- **Markdown** — Clear headings, short paragraphs, code examples.

---

## Pull Request Process

1. **Keep it focused** — one feature or fix per PR
2. **Write a clear title** — "Add X feature" not "stuff"
3. **Describe what changed** — why, what, how
4. **Test it** — make sure it actually works
5. **Reference issues** — if fixing a bug, link the issue
